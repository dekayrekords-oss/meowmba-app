# Build 206: native model response recovery for commercial capture

Branch: `fix/litert-runtime-fallback-206-20261004`; baseline camera build205, commit `03fada5`. Codex is the sole build owner;206 allocated, next207.

The purple-dragon request on the capture emulator reached a successfully initialized GPU engine but returned a native `INTERNAL` error from `convert_tensor_buffer.h:134` and `litert_tensor_buffer.h:861`. Evidence remains in `work/commercial204/gemma-avatar-fast-failure-logcat.txt` outside the app repository. The previous GPU-first policy fell back to CPU only during initialization, so this response failure stopped creation.

The same model now gets one CPU retry for those known buffer errors, only before answer output. The GPU conversation must finish cleanup first; the shared model pool closes its GPU engine before loading the CPU replacement. A resident CPU engine is reused by newly created provider wrappers. Existing settings, thread counts, output budgets, schema, local task deadlines, permissions and on-device routing are retained. CPU failures, unrelated errors, partial responses, cancellation and cleanup failure do not authorize another attempt. No cloud fallback is added. Flow error conversion also preserves downstream exception transparency.

Nine regression cases exercise actual callback/session and shared-pool ownership: close session, close GPU engine, load CPU, generate, close CPU session. They also cover CPU failure, existing initialization fallback, partial answer, completion, unrelated error, cancellation, failed cleanup and downstream failure.
