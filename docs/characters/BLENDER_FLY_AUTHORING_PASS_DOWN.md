# Blender fly source authoring pass-down to Meow

`scripts/build_fly_blender.py` authors the character entirely from editable volumetric geometry. It uses the same native renderer proportions/colors: local foot bottom about−1.09, root scale .50, standing root y1.35, green segmented abdomen, charcoal head/thorax, red eyes, six limbs, short bristled antennae, small mouth, curved thick wings. The Blender axis mapping is explicitly converted to runtime X-right/Y-up/Z-front. Hierarchical empty joints control separate editable meshes; this is an articulated hierarchy, not a skinned armature.

Run on Meow with the approved portable Blender4.2 executable:

```sh
/home/prog/tools/blender-4.2/blender-4.2.0-linux-x64/blender -b --python scripts/build_fly_blender.py -- --output-dir art/avatars/cartoon-fly-3d --render --resolution 900 --samples 48
```

Outputs: `cartoon-fly.blend` (editable full scene), `cartoon-fly.glb` (character and named animation tracks), `fly_meshparts.json` plus deterministic gzip, five perspective PNGs (front/quarter/side/back/flight-quarter), and `manifest.json`. The script uses EEVEE cel bands and reversed-normal black hull geometry for previews. GLB uses portable PBR base-color materials, with shader appearance supplied by the consuming app. Exported GLB animation JSON is parsed to verify fly/walk/wave/talk/blink tracks; a missing clip is an error, not silently claimed complete.

Meshparts schema version1: `nodes` contain name/parent and column-major localMatrix in runtime coordinates. `meshes` contain node name, expanded positions/normals, triangle indices, linear RGBA color and transparency flag. Runtime outline hull duplicates are omitted. Root rest translation is y1.35; a runtime importer should replace the root transform with the simulation root and keep the .50 authoring scale. No runtime loader was added in this worker task: the current Android renderer remains the separately authored native mesh implementation with matching proportions, not an imported GLB. The JSON enables a future importer without claiming one already exists.

Animation editing: each animated object has same-named NLA tracks so matching channels export into one clip. Muted tracks preserve the editable neutral rest pose; export temporarily unmutes them with no extrapolation. The .blend saved before export keeps native toon materials. The script does not download, install, run subprocesses or call external services. It contains no exact-video-likeness claim; the supplied references inform an original fly design.

Validation by worker: Python syntax compilation and `git diff --check` passed. Parent owns the real Blender execution, render inspection, APK build/device deployment and git commit. Source authoring is ready; successful rendered/exported artifacts must be confirmed from the server manifest and actual images before reporting completion. For future Blender failures, inspect the exact exception; shader nodes require EEVEE, glTF options are filtered against the installed operator schema, and clips are independently checked in GLB JSON.

## Verified Blender4.2 exporter state repair

The first real preview exposed a Blender4.2 NLA export restoration bug: export left `rig_root.location=(0,0,0)` instead of the authored height1.35, shifted `leg_L_upper` local Z from−.57 to−3.67, and displaced wing joints below the floor. The saved pre-export .blend remained correct and rendered a complete character directly. The broken after-export preview therefore showed isolated appendages and table occlusion, not missing meshes or a camera failure.

The authoring script now captures every authored rest transform before export, restores those TRS values in GLB nodes after export (while preserving valid animated channels/binary data), and reopens the saved .blend before still rendering. It rebuilds animation-track handles after reload so no stale Blender object references survive. On Meow Blender4.2 the regenerated exporter completed and verified all five named clips. Parent/worker inspect the resulting PNGs; do not accept file existence as proof of visible character geometry. Future Blender upgrades should compare root/joint rest transforms in both .blend and GLB and render at least front, quarter and back after animation export.

Worker visual verification after repair: inspected the actual regenerated full-resolution quarter PNG and diagnostic copies of front, side, back and flight-quarter. Every view shows the complete connected character; the side/back have distinct volumetric silhouettes and the flying pose has raised legs. Independently parsed the repaired GLB and verified rootY1.35, leg localY−.57, a non-identity wing rest quaternion, and all five named animation clips. A second Blender invocation passed newly added per-node rest-location/scale assertions. PNG rendering and Blender export are now verified; this remains separate from Android runtime/phone performance verification.

Final distribution verification: connection recovered and all five corrected full-resolution PNGs, repaired .blend/.glb, fresh meshparts gzip and manifest were synchronized locally. Each PNG passed complete chunk CRC validation; the gzip parses as schema1 with72 mesh parts. The uncompressed JSON duplicate and small diagnostic JPEGs were moved to ignored `build-out/blender-authoring/`; committed distribution keeps gzip only. `manifest.json` explicitly omits the raw JSON and documents that it is reproducible by decompression. The authoring script may still generate raw JSON for inspection; it is not needed in the delivered set. No stale or partial previews remain in the distribution directory.
