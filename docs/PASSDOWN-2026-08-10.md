## Open work, ranked

### Tier 1 — real engineering

- **Face-track staircase** (`VisionManager.kt:338`). Gaze passes a dead-band, a
  `maxStep` clamp, AND a second dead-band in `CompanionViewModel`, so it arrives
  as discrete jumps rather than a stream the renderer spring can integrate.
  Keep one dead-band, drop `maxStep` (the EMA already bounds the rate), publish
  on a fixed cadence.
- **`mouthEnergy` recomposes the avatar ~14×/sec while speaking**
  (`CompanionViewModel.kt`). Same class of bug the `AvatarRenderer` refactor
  just fixed, different field: move it out of `CompanionState` into its own
  `StateFlow` and read it as a lambda inside the draw pass.
- **IMU/face-track servo writes still dispatch on the main thread at ~50Hz.**
  The `println` flood is gone; the dispatch is not. Route `setServo` through a
  conflated channel on `Dispatchers.IO`, register the sensor on a
  HandlerThread.
- **Duplicate GATT connect storm.** Earlier logs showed ~8 concurrent
  `LooiBleLink` connections in 20ms, each queuing 39 init ops. Latest build
  shows only one, so it may be incidentally fixed — but the cause inside the
  attach path was never found. Confirm or fix properly.

### Tier 2 — animation catalogue quality

- **11 keyframe built-ins are permanently unreachable** — a composed expression
  owns the same name, and `playAnimationNamed` resolves composed first.
- **Four expression pairs are effectively identical**: `head bonk`/`bunt`,
  `content sigh`/`relief`, `groom`/`paw lick`, `zoomies`/`zoomies burst`. The
  catalogue advertises more behaviours than exist.
- `EyeL.WIDE` and `EyeL.ALERT` render nearly the same once clamped — re-space
  them on pupil size and aspect so the eye ladder has real steps.
- `Body.RECOIL` is at full amplitude on frame 0 (no anticipation); `Body.COIL`
  ends mid-launch and cuts.
- Ear/jaw rhythms run on *normalised* clip time, so the same channel plays at a
  different speed in every expression. Pass absolute seconds.
- `JawL.PULSE` straddles the `MouthMode` threshold, so `purr` strobes between
  HAPPY and SPEAKING nine times.
- `quick blink` is 0.45s — below the visibility floor. Keyframe built-ins push
  `eyeOpen` to 1.4–1.6, the same bug-eyed look fixed on the composed path.
- `applyTo` fires sparkle on `startle`/`recoil`/`surprise` — delight VFX on a
  fear beat.

### Tier 3 — cheap correctness

- `CommandHeuristics` (`LlmToolCallRouter.kt:29`) blocks alarm/timer/volume
  words from the LLM fallback, so anything the keyword path misses dies.
- Bare `open ` rule swallows the vault-note and camera rules declared below it.
- `WakeWordService` never wires `onMicUnavailable` — a yielded mic leaves the
  foreground service alive holding `MicOwner`, listening to nothing.
- `TextToSpeechManager` can silently swallow an utterance, so
  `onSpeechFinished` never fires. The new THINKING watchdog masks this; the
  cause is unfixed.
- `DownloadService` fires `NotificationManager.notify()` every 64 KB — tens of
  thousands of binder calls per model download.
- `EncryptedSharedPreferences` is constructed/read ~40× on the main thread
  during cold start.
- `ScreenWatchService` captures full-screen frames on the main thread and
  ignores `ImageReader` rowStride.
- `MeowAccessibilityService.findNodes()` recycles a node then keeps reading it.
- Replaying the same expression twice in a row plays nothing — the effect is
  keyed on the expression value. Needs a monotonic `animationPlayId`.

## Landmines worth knowing

- **AiAi serves ONE recognition session per app.** Separate `SpeechRecognizer`
  instances refuse each other. If the mic, wake word and always-on listening all
  break *together*, that is the signature. A wedged AiAi holds a
  `VOICE_RECOGNITION` capture with no `rec stop` in `dumpsys audio`; clear with
  `adb shell am force-stop com.google.android.as`.
- **A connected LOOI base is invisible to every BLE scan.** Absent-from-scan and
  working-correctly are the same state. Check the GATT log first.
- **The saved robot MAC was pointing at a Bluetooth speaker** (`2BOOM-BT295`,
  `41:42:CF:AD:7F:81`). The class filter stops that recurring, but the stale
  value may still be in encrypted prefs — clear the field in Settings.
- **The phone drops off USB repeatedly.** Four times this session. Wireless
  debugging is worth setting up.
- `spin` was deliberately moved from the face to the body, and the test that
  pinned the old behaviour was updated rather than left lying.
