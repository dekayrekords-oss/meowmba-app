# Candidate150 tester checklist

Test only synthetic content and accounts you intend to connect. Report device/Android
version, app version, exact steps, expected result and actual result. Settings → Help &
feedback → Share diagnostics can export a bounded metadata report. Never include keys,
passwords, private messages or recordings without deliberate consent.

## Everyday acceptance

1. Fresh installation: launch, choose/skip a provider, deny optional permissions, return
   later, and verify that setup explains what is still needed. Do not reset an existing
   personal installation to simulate first run.
2. Upgrade: verify existing chat, memories, provider configuration and appearance survive.
3. Voice: consented quiet/noisy tests, names, interruptions, silence, denied microphone,
   offline state and provider failure. No duplicate replies or stuck listening.
4. App lifecycle: rotate/fold, use large text, background/return, screen off/on and reboot.
5. Computer: configure/reconnect, use a synthetic task, approve one exact file, deny another,
   cancel, follow up, Save & preview and find the saved result in Files.
6. Generation: request an avatar/prop, inspect preview, refine, retry a provider failure,
   cancel before completion, and verify only the approved output becomes equipped.
7. Privacy: mic/camera controls and stop/revocation behave as shown. Optional modes remain
   off unless explicitly enabled. Share diagnostics only to a chosen destination.
8. Endurance: ordinary use and an unplugged idle observation; record ambient conditions,
   brightness, charging state and workload. Stop if uncomfortable; do not override Android
   thermal protection. A warm charging phone alone cannot identify the app as the cause.

## Known scope

The Play edition has no autonomous Accessibility phone-screen control. Small verified
Computer exports work; large transfers and unified project workflows are unfinished.
Physical robot motion remains disabled. Optional glasses, cover-display, HUB and neural
features are not broadly hardware-certified. Native model compatibility on older arm64
phones and all-day thermal/battery behavior still need acceptance.

## Play production access

At the September19 inspection,12 testers had been opted in for9 continuous days. Keep
at least12 opted in through the required14-day period. Record actual usage and feedback;
opt-in duration alone is not evidence that every feature was exercised. Apply for production
access only when the Console enables the application and readiness evidence is sufficient.
