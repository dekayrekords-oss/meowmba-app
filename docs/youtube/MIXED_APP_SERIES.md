# Simple ideas and mixed app-building episodes

Owner direction, 2026-09-13: cover all apps we are making and will make, mixing simple app ideas with how we make them. Existing Meow videos remain useful as one project series. This document proposes content; it does not authorize starting every proposed app or claim that any of them exists.

## Small app ideas to choose from

| Proposed concept | Everyday problem | Smallest useful version | Build lesson |
|---|---|---|---|
| One-button idea notebook | An idea disappears before you save it | Type an idea, save it, reopen the list | Input, local persistence, empty states |
| Where did I put it? | Forgetting where an item is stored | Save item and location, then search | Simple data model and search |
| What should I cook? | Not knowing what to make with available ingredients | Enter ingredients and filter a small recipe list | Filtering and honest data limits |
| Tiny project checklist | Losing track of the next step | Create a checklist and check off tasks | State updates and persistence |
| Before-you-leave checklist | Forgetting keys or another essential | Reusable checklist with reset | Reversible actions and clear controls |
| Photo naming helper | A batch of photos has confusing names | Preview a naming rule on sample filenames | Validation, preview, collision handling |

These are suggestions, not a verified inventory of existing apps. A concept may overlap an existing project; check before creating another repository. Keep the first version small and add accounts, cloud sync, or AI only if the selected idea actually needs them.

## One idea can become several different videos

- Idea: show the problem and sketch the smallest solution.
- Build: implement one working path and explain the choices.
- Demo: show how someone uses the finished milestone.
- Debug: cover a real failure encountered along the way, if there is one.
- Follow-up: add a feature based on actual use or feedback.

Do not invent a bug just to fill an episode slot. Mix these with existing-project updates so viewers see different apps and types of work.

## Build episode outline

1. “Here’s the problem I want this app to solve.”
2. Sketch one screen and define the first useful result.
3. Show a few meaningful implementation decisions, with readable code.
4. Demonstrate the working flow using test data.
5. Try an edge case and explain the result.
6. State what is complete and what could come next.
